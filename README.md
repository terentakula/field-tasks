# Field Tasks — тестовое задание React Native Intern

**Код кандидата: ALEX-123**

Мобильное приложение для выездных техников: создание, планирование, отслеживание и просмотр рабочих задач. Работает без интернета и синхронизируется с мок-сервером REST.

## Возможности

- Создание, редактирование и удаление задач: название, описание, дата и время, адрес, точка на карте, вложения
- Валидация с понятными сообщениями об ошибках; срок новой задачи должен быть в будущем
- Список задач с сортировкой по дате добавления, сроку и статусу; состояния загрузки и пустого списка
- Детальный экран со сменой статуса (In Progress, Completed, Cancelled) и историей задачи
- Вложения (изображения и PDF) копируются в папку приложения и сохраняются после перезапуска; недоступный файл показывается как «Unavailable»
- Локальное напоминание за 30 минут до срока и демо-режим (напоминание через 45 секунд после сохранения)
- Карта с маркерами задач; нажатие на маркер открывает задачу
- Вкладка History: создание, редактирование, смена статуса, изменения вложений, удаление и события синхронизации с временем
- Офлайн-режим: всё хранится локально, изменения отправляются на json-server, когда появляется связь
- Статус синхронизации у каждой задачи: Pending sync, Synced, Sync failed

## Технологии

- **Expo + React Native + TypeScript** — быстрый старт, сборка APK через EAS, готовые модули для уведомлений, файлов и выбора изображений
- **Zustand + persist (AsyncStorage)** — простое управление состоянием со встроенным сохранением
- **React Hook Form + Zod** — состояние формы и правила валидации в одной схеме
- **React Navigation** — нижние вкладки (Tasks, Map, History, Settings) и стек поверх них для деталей и формы
- **expo-notifications** — локальные напоминания
- **expo-image-picker, expo-document-picker, expo-file-system** — вложения
- **react-native-webview + Leaflet** — карта без API-ключа
- **@react-native-community/netinfo** — отслеживание появления сети для синхронизации
- **json-server** — мок REST API

## Запуск

```bash
npm install
npm run server        # json-server на порту 3001
npx expo start        # запуск в Expo Go (уведомления там отключены, см. ограничения)
```

## Мок-сервер

1. `npm run server` запускает json-server с файлом `server/db.json` (есть тестовые данные) на `0.0.0.0:3001`.
2. Узнайте локальный IP компьютера (`ipconfig` в Windows, `ifconfig` в macOS/Linux).
3. В приложении откройте **Settings → Mock server URL** и введите `http://<ваш-ip>:3001`.
4. Телефон и компьютер должны быть в одной Wi-Fi сети. В Windows разрешите Node.js в брандмауэре для частных сетей.

## Архитектура

```
src/
  components/   переиспользуемые компоненты: TaskCard, StatusBadge, AttachmentThumb
  navigation/   вкладки + стек, типизированные маршруты
  screens/      Tasks, TaskForm, TaskDetails, Map, History, Settings
  services/     синхронизация, уведомления, вложения
  storage/      сторы Zustand (задачи + история, настройки)
  types/        общие типы TypeScript
  utils/        сортировка, форматирование, валидация
```

- **Хранение.** Задачи и история лежат в одном сторе Zustand и сохраняются в AsyncStorage. Изменение задачи и запись в истории сохраняются одним обновлением. Экраны читают данные через селекторы.
- **ID.** Генерируются на устройстве (UUID), потому что задачи создаются без связи с сервером.
- **Синхронизация.** У задачи есть `syncStatus` и `updatedAt`. Синхронизация запускается при появлении сети (NetInfo), каждые 30 секунд и кнопкой в Settings. Несинхронизированные задачи отправляются через POST/PUT. Удалённые задачи сначала помечаются (`deleted: true`), удаляются на сервере и только потом стираются с устройства — иначе удаление без интернета не дошло бы до сервера, и задача вернулась бы. Конфликты решаются по принципу **last-write-wins** по `updatedAt`. Задачи, которые есть только на сервере, загружаются на устройство.
- **Найденный и исправленный баг:** удалённые задачи могли возвращаться после синхронизации, потому что загрузка сравнивала данные со списком с сервера, полученным *до* удаления. Исправлено повторным запросом к серверу после отправки изменений.
- **Уведомления.** Напоминание ставится за 30 минут до срока. Если до срока меньше 30 минут, оно приходит через 5 секунд. Если срок прошёл, напоминание не ставится. Напоминание отменяется при завершении, отмене и удалении задачи и переназначается при редактировании.
- **Карта и место.** Адрес вводится вручную. Координаты выбираются из списка готовых мест (это разрешено ТЗ). Карта — Leaflet в WebView с плитками Esri, API-ключ не нужен.
- **Вложения.** Выбранные файлы копируются в папку документов приложения; в задаче хранятся только метаданные (путь, имя, MIME-тип).

## Ограничения и компромиссы

- **Нет тёмной темы** — не успел реализовать в отведённое время.
- **Уведомления отключены в Expo Go** (в новых версиях SDK их убрали из Expo Go); проверять их нужно в APK. Некоторые производители (например, Xiaomi) задерживают фоновые уведомления из-за экономии батареи — для приложения нужно выставить режим батареи «Без ограничений».
- **Карте нужен интернет** для загрузки плиток. В продакшене я бы использовал нативный MapLibre.
- **Нет геокодинга** — координаты выбираются из готового списка.
- **Вложения остаются на устройстве**, синхронизируются только их метаданные. Файлы, удалённые из задачи, не удаляются с диска.
- **Last-write-wins** зависит от точности часов устройства.
- Запись «edited» в истории не показывает, какие именно поля изменились.
- Нет юнит-тестов.
